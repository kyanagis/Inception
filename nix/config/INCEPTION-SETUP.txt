Inception x86_64 Universal OVA
============================

このOVAは特定のsubmit commitを内包・固定しません。
VirtualBoxへ一度importした後、通常のsubmit変更ではOVAを再生成しません。

GUI
---

DesktopにはTerminalとText Editorを用意しています。
TerminalはSuper+Enterでも開けます。Text EditorはMousepadです。
GUIに問題がある場合はCtrl+Alt+F2でTTYへ切り替えられます。

1. 初回設定
-----------

OS account: inception
初期password: inception

最初にpasswordを変更し、42 loginを設定します。

    passwd
    inception-setup YOUR_42_LOGIN

2. cloneして起動
---------------

    cd /home/inception
    git clone --branch submit --single-branch \
      https://github.com/kyanagis/Inception.git Inception
    cd Inception
    make

これだけでOVAのidentityを読み、srcs/.envを生成し、host ABIを確認して
mandatory stackを起動します。make host-setupはOVA内では実行しません。

確認:

    make test
    make status

3. 完全評価
-----------

OVA管理のdisposable checkoutでcurrent submitを完全評価する場合:

    inception-evaluate --full

project内部の評価手順はsubmit/.inception/evaluateが所有します。
そのためMakefileや内部script構成が変わってもOVA側を変更する必要はありません。

4. host-level変更
-----------------

kernel/Docker/firewall/host toolingなど、submitだけでは吸収できないhost capabilityが
必要になった場合もOVAの再export/importは不要です。

    inception-host-update

またはsubmit側の .inception/host-abi が新しいABIを要求すると、makeが必要時だけ
inception-host-update --ensure を呼びます。更新はcurrent mainの
nixosConfigurations.inception-runtimeをnixos-rebuild switchで適用します。

5. userspace依存
----------------

submit/.inception/host-tools に不足commandを宣言すると、inception-evaluateは
ephemeral Nix shellで補完します。

6. 診断
-------

    inception-audit
    inception-evaluate --prepare
    ssh-setup --status

再生成が必要になるのは、x86_64から別architectureへ変更する場合、VirtualBoxの
仮想hardware定義そのものを変更する場合、またはguestがbootできないほどbootstrapを
破壊した場合です。
